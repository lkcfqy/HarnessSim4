# 真实工位数据采集协议 v0.1

## 首次采集范围

只选一个产量较高、结构适中、能取得授权的端子—护套 SKU。第一轮不追求自动散乱供料，
允许人工把端子/线缆放入可重复的预定位槽，从而把问题聚焦到对准、插入和锁止验证。

建议初始数据量：

- 60–100 次人工或示教器引导的成功插入；
- 20–30 次受控失败，包括横向偏差、角度偏差、端子旋转、半锁止和安全范围内的卡滞；
- 至少 3 个不同采集日、2 批物料、2 名操作者；
- 先做小样本检查同步与标签，再开始大批量采集。

故意制造失败前必须由设备和工艺负责人确认不会损坏工装、端子或造成人员风险。

## 建议的 LeRobot 兼容字段

| 字段 | 频率 | 内容 |
|---|---:|---|
| `observation.images.overhead` | 30–50 Hz | 固定相机 RGB，覆盖护套、端子和夹具 |
| `observation.images.wrist` | 30–50 Hz | 腕部近景 RGB，可选深度 |
| `observation.state` | 与控制周期一致 | 关节位置/速度、末端位姿、夹爪状态 |
| `observation.force_torque` | 100–500 Hz 原始；另存同步值 | 六轴力/力矩，保存原始高频流 |
| `action` | 与控制周期一致 | 目标关节/末端动作及控制模式 |
| `terminal_pose` | 每帧或关键帧 | 位置、姿态、置信度、标注来源 |
| `connector_pose` | 每帧或关键帧 | 位置、插入轴、置信度、标注来源 |
| `contact_state` | 事件+帧 | free/contact/aligned/inserting/locked/jammed |
| `episode_index`, `frame_index`, `timestamp` | 每帧 | 单调时间戳，不使用文件创建时间代替 |
| `outcome` | 每 episode | success/failure/recovered/aborted |
| `failure_reason` | 每 episode | perception/fixture/contact/control/feed/unknown |
| `connector_sku`, `terminal_sku`, `lot_id` | 每 episode | 内部匿名 ID；敏感映射另存 |
| `calibration_id`, `station_id`, `operator_id` | 每 episode | 可追溯但去标识化 |

相机、控制器和力传感器应使用同一时钟或记录可估计的时钟偏移。每次开机、更换相机/夹具、
发生碰撞或误差异常后重新标定，并保存 `calibration_id`。

## Episode 边界

一次 episode 从机械臂位于安全预备位、端子和护套已就绪开始，到以下任一条件结束：

- 锁止检测通过且机械臂安全退出；
- 失败恢复完成；
- 触发超时、限力、急停或人工中止。

不要删除失败轨迹。失败和恢复正是模型与产品壁垒的重要组成部分。

## 切分原则

第一版至少保留三套评估：

1. **同分布测试**：未见过的完整 episode；
2. **跨日测试**：整个采集日只放入测试集；
3. **跨批次测试**：一个物料批次或轻微夹具重装后数据只放入测试集。

当扩展到多个 SKU 时，再增加“留一 SKU”评估。模型选择只看验证集，最终测试集只在版本
冻结后运行。

## 必报指标

- 首次插入成功率、最终成功率及 95% 置信区间；
- 失败检测的精确率、召回率，特别是半锁止漏检；
- 平均/P90/P99 周期时间；
- 峰值轴向力、峰值侧向力、力冲量；
- 平均重试次数、人工干预率、端子/护套损伤数；
- 按日期、批次、操作者和失败类型分层的结果。

离线动作误差只作为调试指标，不能替代这些闭环指标。

## 权限与保密

- 采集前由德丰确认设备、客户图纸、产品和视频的授权边界；
- 人脸、工牌、屏幕、客户名称和图纸尽量不进入画面；
- 公开论文优先发布匿名化特征、合成数据或另行制作的实验室数据；
- 原始客户数据设置访问日志、备份、保留期限和删除流程；
- 任何上传云端或跨境传输都要先完成企业与客户审批。
